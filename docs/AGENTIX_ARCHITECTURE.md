# Agentix — архитектура платформы интеграции Velyon Core

**Состояние:** архитектурный каркас и информационный раздел. **Публичное подключение не открыто.** Этот документ фиксирует целевую систему, а не заявляет о готовности перечисленных API.

## 1. Продукт и границы

**Agentix** — платформа интеграции интеллектуальных возможностей Velia в сторонние SaaS, сайты, приложения, корпоративные системы и устройства. Название ассистента — Velia, интеллектуального ядра — Velyon Core. Внешние клиенты могут выбрать видимый бренд Velia или White Label с отдельной политикой отображения бренда, согласованной в договоре.

Цель: разработчик подключает готовые диалоги, поиск по знаниям, голос, интеллектуальные агенты и автоматизацию задач к **своему** приложению. Клиент владеет бизнес-логикой, пользователями и источниками данных. Agentix исполняет лишь разрешённые операции.

Не смешивать Agentix с разделом «Мои агенты»: «Мои агенты» — личная функциональность Velia, Agentix — независимая платформа для **внешних продуктов**. Не смешивать и с Developer API DeepAlpha: его существующий кредитный контур можно переиспользовать после аудита, но его ключи/права и продукты не должны автоматически открывать доступ к Agentix.

### Формы продукта

- **Agentix API:** серверное подключение по HTTP/streaming, вызов моделей и инструментов, контексты диалогов, асинхронные задачи.
- **Agentix Embed:** UI-компонент для сайтов и SaaS со своей областью данных, темой, языками и политиками поведения.
- **Agentix Agents:** агенты и процессы с инструментами клиента, контролем разрешений, согласованиями, расписаниями и webhooks.

SDK: JavaScript/TypeScript и Python; в дальнейшем мобильные SDK и MCP-совместимые инструменты с проверенными полномочиями.

## 2. Общая схема

~~~text
Пользователь чужого продукта / сотрудник компании
          |
          v
[Клиентский SaaS / сайт / мобильное приложение]
          |  Agentix SDK / Embed / Server API
          v
+---------------- Agentix Control & Data Plane -----------------+
| API Gateway: TLS, auth, scopes, rate limit, request-id        |
| Organizations / Projects / Environments / Service Accounts    |
| Policy Engine: RBAC + scopes + action risk + approvals        |
| Usage Meter: quotas, credits, cost, ledger, spend limits      |
| Session Orchestrator: context, memory, idempotency, streaming  |
| Velyon Core Router: Flash / Quantum / PRO                     |
| Capabilities: chat, voice, knowledge, vision, tools, agents   |
| Jobs: queue, leases, retries, outbox, webhooks, audit         |
+---------------------------------------------------------------+
          |                     |
          v                     v
[Разрешённые данные]   [Инструменты и API клиента]
          |
          v
[Ответ с метаданными, событиями и расходом]
~~~

**План размещения:** пользоваться существующими GitHub-репозиториями, Railway-окружением, сервисными процессами и PostgreSQL. Не создавать новые проекты, контейнеры и платные ресурсы, пока нагрузочные замеры не подтвердят необходимость.

### Плоскость управления (Control Plane)

Управление организациями, проектами, средами, сотрудниками, API-ключами, коннекторами, квотами, тарифами, журналами, политиками хранения и выставлением счетов. Управление доступно только после аутентификации и проверки принадлежности к организации.

### Плоскость запросов (Data Plane)

Непосредственное выполнение чатов, поиска, задач и инструментов. Для каждого запроса передаётся **серверно подтверждённый** контекст организации, проекта, окружения, пользователя, выбранных разрешений и бюджета. Аутентификационные claims нельзя брать из свободно редактируемого JSON-тела.

## 3. Сущности и отношения

| Сущность | Смысл и граница |
|---|---|
| Organization | Юридический или личный владелец интеграций; изолированная область |
| Membership | Связь сотрудника с организацией и его роль |
| Project | Продукт компании, владеющий настройками, инструментами и квотами |
| Environment | Отдельные test/live ключи, данные, callback адреса и бюджеты |
| API Key / OAuth Client | Серверные секреты, сроки, права, ротация, отзыв |
| End User | Локальная идентичность конечного пользователя внутри проекта |
| Conversation | История и настройки только в пределах проекта и End User |
| Knowledge Source | Документы, индексы и правила доступа проекта |
| Connector | Определение доступных действий, авторизация, лимиты |
| Agent Template | Цели, инструменты, ограничения, модель, персонализация |
| Agent Job | Долгая задача со статусом, lease, бюджетом и idempotency |
| Approval | Одноразовое подтверждение конкретной операции |
| Usage Event / Credit Ledger | Учёт выполненных операций, возвратов и списаний |
| Audit Event | Неподменяемый журнал управления доступом и внешних эффектов |

Каждая ресурсная таблица должна содержать organization_id и project_id; там, где применимо, также environment_id и end_user_id. Для SQL-запросов применить серверные проверки связей и ограничители на уровне БД. Foreign key должен запрещать ссылку на ресурс другого проекта. Для high-risk классов запросов полезен PostgreSQL RLS как дополнительный барьер, но он не заменяет проверку уровня сервиса.

## 4. Доступ и безопасность

1. **Только подтверждённая серверная идентичность:** ключ -> клиент -> организация/проект/среда -> права. Не использовать идентификаторы из браузерского payload как доказательство владения.
2. **Scopes по возможностям:** например agentix:chat:read, agentix:agent:read; отдельные scopes для действия, знаний и управления. Выдача ключей — server-side, с однократным показом секрета и безопасным хранением хэша.
3. **RBAC:** owner, admin, developer, analyst, billing, viewer, service-account. Роли ограничивают администрирование; пользовательский доступ к данным проверяется отдельно.
4. **Действия:** read / write / external / critical. Действия, меняющие данные или оказывающие внешнее влияние, требуют серверной проверки конкретного tool+args и подтверждения там, где нужно. Разрешения не выводить из текста пользователя или ответа модели.
5. **Approval:** неизменяемый отпечаток аргументов, ресурс, субъект, срок жизни, одноразовая nonce, повторная проверка до исполнения; при изменении аргументов подтверждение аннулируется.
6. **Изоляция:** запросы, память, RAG-индексы, кэши, файлы, логи, фоновые задачи и сессии браузера имеют жёсткую границу организации/проекта/пользователя; запрет сквозных чтений и инъекций инструкций из документов.
7. **SSRF и коннекторы:** запрет произвольных callback/internal URL, allowlist внешних доменов, проверка DNS/IP/redirect, хранение OAuth токенов шифрованно, минимальные разрешения, ротация секретов.
8. **Конфиденциальность:** конфигурируемое хранение и удаление, пользовательский экспорт, удаление источников, минимизация PII, отдельная политика для sensitive data и регуляторных случаев.
9. **Web/Embed:** сервер выдаёт короткоживущий подписанный сеансовый токен, привязанный к project_id, end_user_id и разрешённому origin. Секреты API запрещены внутри JavaScript SDK и виджетов.
10. **По умолчанию запрет:** незнакомые инструменты, незавершённая авторизация, истекшие ключи, межпроектный доступ, превышенный бюджет и операции без подтверждения отклоняются.

Текущий код в agentix/*: **только типизированные контракты**, проверка границ и fail-closed policy. Никакие API endpoints, разрешения на запись или платежи сейчас не зарегистрированы. Даже ручное включение runtime-флага не подключает исполнителя.

## 5. Контракты API (проект, не работающие маршруты)

Запланированная независимая область: /agentix/v1/ — без переиспользования /api/v1/ DeepAlpha и /api/mobile/ Velia как открытого контракта.

~~~http
GET    /agentix/v1/capabilities
POST   /agentix/v1/responses
POST   /agentix/v1/conversations
GET    /agentix/v1/conversations/{id}
POST   /agentix/v1/knowledge/sources
POST   /agentix/v1/agents/runs
GET    /agentix/v1/agents/runs/{id}
POST   /agentix/v1/agents/runs/{id}/approvals
POST   /agentix/v1/webhooks
GET    /agentix/v1/usage
~~~

### Будущий запрос

~~~json
{
  "conversation_id": "conv_example",
  "capability": "chat",
  "mode": "flash",
  "input": [{"role": "user", "content": "Подготовь сводку по заказам"}],
  "tools": ["orders.read"],
  "client_request_id": "req_example"
}
~~~

### Будущий ответ

~~~json
{
  "id": "response_example",
  "status": "completed",
  "output": [{"type": "text", "content": "Сводка подготовлена."}],
  "usage": {"input_units": 0, "output_units": 0},
  "request_id": "req_example"
}
~~~

Значения — иллюстрации структуры, не реальные ответы сервиса. Результаты чтения и write-действий должны быть машиночитаемо разделены. Потоковые события предусматривают start/delta/tool_request/approval_required/completed/error, последовательность и восстановление курсора. Не повторять внешнее действие автоматически после неопределённого сетевого исхода.

## 6. Работа агентского цикла

~~~text
Ввод -> auth -> tenant/project/end-user policy -> budget reserve
     -> intent -> model route -> permitted tool selection
     -> validate arguments -> risk classification
     -> if write/external: approval -> single dispatch receipt
     -> tool execution (bounded) -> evidence/result review
     -> usage settlement -> audit/outbox -> response/webhook
~~~

Инварианты: одна подтверждённая команда — не больше одного внешнего исполнения; ограниченные попытки на read-only шагах; отложенные задачи переживают рестарт; отмена запрещает последующие шаги, но не обещает откат уже выполненного действия; jobs имеют lease+fencing; webhooks подписаны HMAC и доставляются с ограниченными повторами; входящие webhook события проверяются на повторы.

## 7. Модели и функции

Режимы API: **Flash** — быстрые ответы; **Quantum** — сложные задачи и разбор; **PRO** — расширенные сценарии. Возможности: текст, потоковый вывод, голосовые интерфейсы, анализ документов, знания, поиск, агенты, многопользовательская работа, интеграции. Реальная доступность каждой функции задаётся capability registry и контрактами; интерфейс не должен обещать отсутствующие функции.

Для агентов предусмотреть независимые права на поиск, чтение данных, создание черновика и внешнюю запись. Не разрешать универсальный «доступ ко всему» по одному флагу.

## 8. Надёжность и эксплуатация

- Производственный путь: gateway -> авторизация -> маршрутизатор -> исполнитель -> хранилище/очереди; закрытые межсервисные вызовы.
- Запросы: correlation/request IDs, rate limiting per key/project, deadlines, circuit breakers, backpressure, retry только безопасных idempotent операций.
- Задачи: bounded queue, leases и retry/fencing, статусные webhooks, явная стоимость и duration.
- Наблюдаемость: p50/p95/p99, success rate, queue lag, errors по кодам, расходы по модели/проекту, злоупотребления; не логировать prompts и секреты по умолчанию.
- Доступность: начало с существующего Railway и PostgreSQL; при появлении нагрузки — независимое масштабирование inference, orchestration и очередей.
- Выпуск: test -> private pilot -> commercial beta -> general availability. Каждый этап имеет интеграционные, нагрузочные, security и billing acceptance tests.

## 9. Тарифы и расчёты

Общая схема: тестовый пакет, предоплаченные кредиты и/или базовая подписка + metered usage. Отдельно считать текст, голос, медиа, извлечение документов, поисковые операции, tool execution и долгие агентские задачи. Перед коммерческим запуском измерить себестоимость и определить резерв/финальное списание/возврат, жёсткие daily/monthly caps, threshold alerts и биллинг каждого клиента. Цены в документе не фиксируются.

Нельзя открывать оплачиваемое действие, пока не проверено exactly-once reservation/settlement, корректное отражение отмен и отказоустойчивость ledger. Оплата не является разрешением на выполнение чужих действий.

## 10. Брендинг и UX

Принципы: отдельный пункт **Agentix** в браузерном меню Velia; понятное подробное описание; без фиктивной формы регистрации или неработающих кнопок. Компании смогут позднее выбирать Velia-branded или White Label и задавать тему, языки и доступные пользовательские операции. SDK не должен обходить серверные ограничения и политики.

## 11. Статус этого изменения

Включено **сейчас**:
- Информационная браузерная страница Agentix, её место в навигации, адаптивный внешний вид.
- Python contracts, policy и отключённая runtime-граница.
- Тестовые проверки основных границ и отключённого выполнения.
- Архитектурная спецификация с дорожной картой.

**Не включено сейчас**: внешняя авторизация клиентов, API endpoints, создание организаций и ключей, соединение с внешними SaaS, webhooks, работающие оплачиваемые вызовы, SDK, самостоятельная регистрация, биллинг Agentix.

## 12. Очередность следующего этапа

1. Аудит и схема данных организаций/проектов/окружений; migration plan и RLS decisions.
2. API security design: токены, scopes, OAuth для инструментов, project ownership и abuse mitigation.
3. Версионированный public API и API testing harness; прослойка adapter к существующему Velyon Core.
4. JavaScript/Python SDK, Web Embed и документированный пользовательский lifecycle.
5. Agents tool registration, evidence, approvals, idempotent jobs и signed webhooks.
6. Metering / ledger / limits / cost accounting и тестовый коммерческий контур.
7. End-to-end тесты с собственным SaaS, затем внешние пилотные клиенты.
8. Privacy policy, legal terms, DPAs, support/SLA, incident response, публичный launch.

**Технический принцип:** Agentix использует уже имеющуюся инфраструктуру там, где это экономически и безопасно; новый ресурс создавать только после подтверждённой необходимости.


## 14. Agentix Business Builder — пользовательский браузерный сценарий

В разделе Agentix есть Business Builder для пользователей без знаний программирования. Сценарий: (1) идея своими словами; (2) необязательные предпочтения по дизайну, возможностям и доставке проекта; (3) обзор и черновик для стандартного чата Velia.

Код браузерного интерфейса: desktop/web/agentix-business-builder.mjs; интеграция в раздел: desktop/web/agentix.mjs, features.mjs и app.mjs; разрешённый статический ресурс — desktop/web_routes.py. Черновик не отправляется автоматически, а переносится в поле ввода чата после явного действия. Пользователь самостоятельно отправляет сообщение. Интерфейс не хранит черновик между аккаунтами, не обращается к внешним API и не инициирует GitHub, ключи, деплой, оплаты и генерацию изображений.

Цветочный магазин представлен CSS-предпросмотром, а не результатом генерации. До реальной разработки Velia уточняет план и критерии приёмки; внешние изменения, публикация, расходы, полномочия Agentix и значимые финансовые действия требуют отдельных разрешений. Будущая реализация должна связать BusinessProject с Software Factory, GitHub/хостингом, полным ZIP, безопасным Agentix Connect и контролируемыми бизнес-инструментами, не создавая дополнительные платные сервисы без необходимости.


## 15. Business Builder — сохранение проектов в аккаунте Velia

Экран Agentix использует существующие owner-scoped `/mobile-api/v1/projects` (через защищённый browser feature proxy), без новых таблиц или сервисов. Поля `passport` ограничены существующим backend: `title`, `goal` (до 1200 символов), `audience` (строго `Agentix Business Builder`), `style`, `constraints`. Список проектов показывается только после авторизации и фильтруется по точному маркеру; все операции на backend проверяют идентичность владельца. Идею, стиль, функции и способ получения можно восстановить из `passport`.

Создание и обновление используют существующий backend с idempotency-key для POST и optimistic `expected_revision` для PATCH; сохранение отсутствует в гостевом режиме. Кнопка продолжения автоматически сохраняет проект (если пользователь вошёл) и подготавливает черновик чата Velia с ID сохранённого проекта. Текущий пользователь подтверждает отправку сообщения отдельно. Этот ID относится к `velia_projects`, **не** к `velia_developer_projects` GitHub/Software Factory, и не означает что запуск разработки произошёл.

Read-only `/mobile-api/v1/developer/factory/status` разрешён в browser feature proxy, чтобы показать реальную доступность инструментов разработки, не открывая опасные endpoints. Если Software Factory выключена или отсутствует GitHub, экран не выдаёт проект за развернутый. Перспективные работы: связать owner-scoped business project с Developer Project через дополнительный защищённый реестр и отдельное подтверждение владельца; далее GitHub, полный ZIP и Agentix Connect.
